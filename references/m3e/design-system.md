# MD3E 设计意识与判断

[English](design-system.en.md)

本文是本 Skill 对 Material 设计资料的编辑提炼，不是官方哲学分类或逐字规范。
依据仓库中保留来源与抓取日期的设计快照；下述判断框架和例子属于本 Skill 的建议。

## 设计立场

把表现力用在帮助用户理解、行动和建立情感联系的地方。先理解用户当前的任务、
内容关系和产品气质，再决定视觉强度。大胆和克制都可以是有意识的选择。

M3E 的运用不依赖某个 UI 框架。既有 Material 基础、项目设计语言和适用的平台惯例
共同构成设计边界；某个组件库没有现成实现，不等于相应设计不可成立。

## 从理念到判断

| 维度 | 需要回答的问题 | 对设计的影响 |
| --- | --- | --- |
| 设计哲学与观念 | 这个界面如何帮助人理解并掌控任务？ | 从任务关系组织界面，避免先挑组件再拼页面 |
| 设计价值观 | 此处更需要效率、信心、探索感还是庆祝感？ | 决定表现力的强度与落点，同一产品可因情境不同而变化 |
| 设计原则 | 用户应先看见什么，哪些内容属于一组？ | 协调强调、分组、反馈和一致性 |
| 设计思维 | 当前问题真的来自视觉样式，还是内容或流程？ | 必要时调整信息组织，不用装饰掩盖结构问题 |
| 设计逻辑 | 视觉重要性是否对应任务重要性？ | 让阅读顺序、操作层级和状态变化互相印证 |
| 设计策略 | 哪一处变化最能改善体验？代价是什么？ | 优先解决关键摩擦，避免把每个位置都做成视觉焦点 |
| 设计语言 | 色彩、字形、形状、空间与动效在表达同一件事吗？ | 建立可识别的角色、节奏和跨界面关系 |
| 设计伦理 | 强调方式是否尊重用户知情与选择？ | 让选项、后果与退出路径清楚，不借表现力诱导误操作 |

这些问题用于形成判断，不要求逐项询问用户或逐项出现在最终输出中。

## 层级与表现力

先辨认当前情境中的主要任务、必要信息和次要选择。通过大小、位置、留白、排版和
对比建立关系，再决定是否需要更鲜明的形状或动效。同等重要的选择应保持可比较，
不能因为某个选项更符合业务偏好就把其他选项隐藏或弱化到难以发现。

表现力可以集中在一个操作、一段关键内容或一次状态变化中。不要把“更有表现力”
理解为所有颜色更鲜艳、所有圆角更大、所有元素都弹跳。也不设定每个产品必须有
固定数量的突出时刻；是否需要，应由任务、频率和产品语境决定。

在列表、表单或高密度工作界面中，清晰的分组、节奏和状态也能形成鲜明的设计语言。
在成功或进度节点中，适度的视觉变化可以突出意义，但不能遮挡下一步操作。

## 以系统关系保持一致

一致性来自相同含义采用相近表达，不要求所有元素外观相同。颜色角色、文字层级、
间距关系和交互反馈应协同工作；局部变化要有可解释的目的。

尊重用户指定的品牌和项目已有设计系统。设计冲突应指出具体影响，并提出能满足任务
的取舍，不擅自替换整套组件库或产品风格。主题生成由项目已有设施承担，本 Skill
指导生成结果怎样用于层级、对比、语义和情境。

## UI Kit 与自主设计

UI Kit 是可复用的设计资源。匹配语义和行为的内容应当采用；只有外观相似、但行为
不符的组件不能直接套用。若没有合适模式，结合规范和用户任务设计自己的组合或组件，
同时复用其中仍然适合的文字、按钮、状态样式等基础内容。

具体判断见 [组件选型与自主设计](components.md)。不要把使用 Kit 当作完成设计思考，
也不要把自行设计当作脱离设计系统的许可。

## 包容性与设计伦理

把可读性、可理解性与可操作性纳入设计本身。结合实际使用方式考虑文字放大、键盘、
触控、辅助技术、不同语言和减少动效，而不是仅用一个规范标签宣称设计合格。

关键状态不能只靠颜色区别；装饰不能压过任务内容。涉及选择和后果时，让文案、强调
和交互反馈如实表达含义。为探索感设计的惊喜，不应出现在用户需要确定性的位置。

## 一个判断例子

同一个习惯记录产品中，每日记录页需要快速扫描和重复操作，周总结页则可能需要强调
进展。前者可以采用有节奏的分组与明确的完成状态，后者可让关键进展获得更强排版和
适度的形状变化。两者共享颜色角色和操作反馈，但表达强度不同。

如果 UI Kit 没有适合周总结的组合，应根据内容关系设计新的总结区域，复用适合的
文本样式和按钮；不要为了套入现有轮播组件而把需要比较的数据拆成互不可见的卡片。
这是情境判断示例，不是所有总结页的固定布局。
